# PERP · perp_db 연결 작업 정리 (2026-09-06)

데모(fixture)/SQLite 기반 프로토타입을 **클라우드 PostgreSQL(perp_db) 실데이터** 로 옮기는 작업의 진행 상황.

---

## 1. 개요 / 배경

- **인증만 perp_db** 였고, 회원가입은 레거시 SQLite, 나머지 화면은 프론트 데모 fixture 를 보여주던 상태에서 시작.
- 목표: **로그인해서 직접 입력한 데이터가 perp_db 에 저장·조회되는 실제 배포 프로그램**.
- 배포 구조: 네이버클라우드 단일 Docker 컨테이너(`orbitflow`)가 **GitHub `main` 을 60초마다 자동 pull → 프론트 재빌드 → 백엔드 재시작**. 즉 `main` 에 push 하면 곧 프로덕션에 반영.
- DB 접속: 컨테이너 → 호스트 PostgreSQL `172.17.0.1:5432`, DB `perp_db`, 사용자 `perpadmin`. 컨테이너 백엔드는 `/opt/perp/app/backend/.env`(호스트 마운트) 로 접속 정보를 읽음. **perp_db 는 서버에서만 접속 가능**(로컬 직접 불가).

## 3. DB 스키마 확장 v3 (구축 완료)

`db/perp_additions_v3.sql` — `db-predesign-reviewer` 검토 → 승인 → `db-builder` 확정 → **서버 psql 적용 완료**. 신규 스키마 2개(`asset`·`automation`) + **테이블 18개**. 전량 신규 추가(기존 테이블 미변경).

| 스키마 | 신규 테이블 |
|---|---|
| **asset**(신규) | assets · reservations(예약 겹침 EXCLUDE) · history |
| **accounting** | budgets · dues_rules · dues_charges(대상자 SET NULL) · dues_payments · settlements |
| **automation**(신규) | workflows(trigger_type) · workflow_runs |
| **ai** | agent_memory · agent_templates |
| **project** | milestones · **tasks**(신설) · task_checklist_items · task_comments · task_dependencies |
| **notice** | notifications(범용) |

- 적용 검증: `asset 3 · automation 2 · accounting 12 · ai 5 · project 15 · notice 4` 로 증가 확인.
- 롤백: 순수 신규 추가라 신규 스키마/테이블만 DROP 하면 됨(롤백 스크립트 준비됨).

## 5. 알려진 이슈 / 한계

1. **기존 자가 가입 계정(test03/ test@naver.com)은 회사가 없음** — 온보딩 도입 전 가입분. 신규 가입은 회사 자동생성. test03 을 계속 쓰려면 회사 부여(백필) 필요.
2. **"자세히" 버튼** — 상세 화면(`endpoint: null`)이 아직 없어 빈 결과. 상세 화면 구축 전까지 불가피.
3. **일부 생성 미구현** — 구성원·업무·결재 등은 아직 조회만. (스텁 생성 버튼은 숨김 처리됨)
4. **커스텀 화면**(근태·휴가·조직도·Vault·예약·조직대시보드) — 전용 컴포넌트라 catalog 연결만으론 안 됨, 개별 작업 필요.
5. **배포 중 순간 빈 화면/403** — 자동배포가 프론트 dist 재빌드·교체하는 몇 초간 자산 404/403 → 빌드 완료 후 정상. 코드 문제 아님.
6. **홈 하단 "요일별 업무 완료" 차트** 등 일부 장식 요소가 fixture 로 남아있을 수 있음(추후 정리 대상).
7. **보안(후순위)** — DB 비밀번호 `root1234`, HTTPS 미적용(80), SSH 비밀번호 노출 이력. 마지막 단계에서 정리.

## 부록 · 재사용 패턴 (신규 모듈 붙이는 법)

- **읽기**: `backend/src/controllers/pgModules.controller.js` 에 회사 스코프 조회 핸들러 추가(응답 `{items:[...]}`, 컬럼 별칭은 한글 가능) → `pgAuth.routes.js` 라우트 등록 → `catalog.ts` 의 화면 `endpoint` 를 `/pg/...` 로 변경. 프론트 제네릭 매퍼(liveTable/liveStats)가 렌더.
- **생성**: `POST /pg/...` 핸들러 추가 + `catalog.ts` 화면에 `create: { endpoint, fields }` 설정 → `CreateFormModal` 이 폼(text·textarea·date·datetime·number·**select(옵션 엔드포인트)**)을 자동 렌더하고 저장·목록 갱신.
- **DB 스키마 추가**: `db-predesign-reviewer`(검토) → 사용자 승인 → `db-builder`(DDL 확정) → 서버 `psql --single-transaction -f`.
