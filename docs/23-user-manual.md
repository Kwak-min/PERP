# 사용자 매뉴얼 (User Manual)

## 1. 시작하기
1. 초대 메일의 링크로 `/signup`에서 가입하면 조직에 합류한다. PG 회사 가입 뒤 초대 수락이 중간에
   실패하면 계정만 남을 수 있으며, 소속이 없으면 접근이 차단된다. 이때는 관리자에게 초대 재발송을
   요청한다.
2. 로그인 후 첫 화면은 **홈**(`/`)이다. 이번 달 요약 수치와 오늘 업무, 승인 대기, 알림을 본다.
   수치 카드에는 기준 시각이 함께 표시된다.
3. 상단바에서 전역 검색(업무·프로젝트·문서·회원·일정·자산)과 빠른 생성을 사용한다. 권한 밖 결과는
   존재조차 표시되지 않는다.

### 사이드바 접기와 즐겨찾기
- 메뉴 그룹 제목을 누르면 접히고, 현재 화면이 속한 그룹은 항상 펼쳐진다. 키보드로도 접기·pin·순서
  변경이 된다.
- 메뉴의 pin으로 **즐겨찾기**에 올리면 사이드바 맨 위에 단축 링크가 생기고 원래 그룹의 링크도
  남는다. 홈은 직접 이동 링크를 유지한다.
- 접힘·즐겨찾기 상태는 **이 브라우저에만 저장되고 다른 기기와 동기화되지 않는다.** 사용자와 회사별로
  따로 저장된다. 권한이 잠시 회수된 메뉴는 저장값을 지우지 않고 화면에서만 숨긴다.
- 채용 화면은 제품에서 제공하지 않는다. 구성원 초대는 구성원 화면에서 계속 사용한다.

## 2. 업무
- `/projects` 목록과 프로젝트 상세, `/tasks`, `/workload` 업무량.
- **프로젝트 구성원 추가**: 선택한 회사의 활성 구성원 중에서 고른다. 이미 구성원인 사람은 후보에
  그 사실이 표시되고 다시 추가해도 중복 생성되지 않는다. 새로 추가되면 참여자 목록이 바로 갱신된다.
  다른 회사·비활성·미승인 회원은 후보에 나오지 않는다.
- 업무를 배정해도 상대에게 권한이 자동으로 생기지 않는다. 권한이 없는 사람은 알림·업무를 못 볼 수
  있다는 안내가 표시된다.
- 필수 체크리스트가 남아 있거나 선행 업무가 끝나지 않으면 완료로 전환되지 않는다.

## 3. 일정과 공간 예약

### 캘린더 (`/calendar`)
- 개인·조직·프로젝트 일정을 월 그리드로 함께 본다. 참석자가 겹치면 생성 시 충돌 경고가 표시된다.
- 일정에서 회의록을 만들면 결정사항 중 **확인한 항목만** 업무로 생성된다.

### 공간 예약 (`/reserve`)
- 흐름은 공간 → 월 → 날짜 → 정확한 시작/종료 시간이다. 월별 예약 현황에서 날짜를 고르면 그 날의
  공간 타임테이블과 빈 시간을 본다. 기본 표시 범위는 08:00~22:00이고 "24시간 보기"로 00:00~24:00을
  본다. 범위 밖 일정을 숨기지 않는다.
- **모든 입력 시간은 서울 시간(Asia/Seoul)**이다. 종료는 시작 이후여야 하며 비교는 `[시작, 종료)`다.
  같은 공간·같은 회사에서 겹치면 409 충돌이며, 실제 동시 요청은 DB 제약으로 하나만 성공한다.
- **반복 예약**은 첫 시작 날짜에 맞춰 만들어진다. 월 반복은 그 달에 없는 날이면 말일로 당겨지고
  다음 달에는 원래 날짜로 돌아간다(1/31 → 2/28 → 3/31). 한 번에 최대 366건이다. 이미 점유된 회차는
  "건너뜀" 목록으로 알려주고 나머지는 생성된다. 그 외 오류는 전체가 취소된다.
- **취소**는 "이 예약만 취소" 또는 "이 예약 및 이후 예약 모두 취소"를 고른다. 과거 회차는 그대로다.
- 예약 수정·취소는 **예약 소유자만** 할 수 있다. 공간 등록·수정·삭제("관리")는 `reservation.manage`
  권한이 필요하다. 다른 사람의 비공개 예약은 제목 대신 "이용 중" 구간만 보인다.
- 참석자는 이름으로 초대·제거한다. 참석자 데이터는 예약과 같은 transaction에 저장되고 안내 발송은
  저장이 끝난 뒤에만 이루어진다.
- 오류가 나도 입력한 값은 유지된다. 400은 입력, 403은 권한, 409는 시간 점유, 503은 예약 서비스
  연결 문제다.

## 4. 문서·회의록
- `/documents` 공간·폴더·태그·버전. 저장할 때마다 버전이 쌓이고 특정 리비전으로 복원할 수 있다.
- `/documents/meetings/{id}` 회의록: 안건·논의·결정사항·담당자·기한. AI 요약에는 항상 근거 링크가 붙는다.
- `/documents/graph`에서 조직 문서 지식 그래프와 회사 LLM Wiki를 쓴다(8절).

## 5. 개인 AI Agent
- `/agent` 채팅, `/agent/brief` 오늘의 브리핑, `/agent/memory` 기억 관리.
- 답변은 **결론 / 근거 / 관련 데이터 / 불확실성 / 추천 다음 행동 / 실행 가능 여부 / 필요한 승인**
  형식이다. 근거가 없으면 불확실성이 표시되며, AI는 승인 없이 데이터를 바꾸지 않는다.
- 기억은 언제든 조회·수정·삭제·전체 초기화할 수 있고, 삭제 즉시 답변에서 제외된다. 비밀번호·인증키·
  주민등록번호는 저장이 거부된다.
- 개인 OpenRouter 키는 `/settings/ai-key`에서 등록한다. 키 등록은 개인 노트의 외부 전송 동의가
  아니며, 민감 등급 데이터는 항상 로컬 모델만 쓴다.

## 6. 개인 Vault (나만의 지식 노트)
- `/vault`에서 개인 노트를 만들고 폴더·태그로 정리한다. 본문에 `[[다른 노트 제목]]`을 쓰면 링크되고
  대상 노트에 백링크가 생긴다.
- `/vault/graph`에서 노트 연결 구조를 **3D 그래프**로 본다. 드래그/방향키로 회전, 휠/+/-로 확대,
  Home으로 맞춤, 아래 목록에서 노트를 선택한다. WebGL을 쓸 수 없는 환경에서는 "이 환경에서는 WebGL
  3D 그래프를 표시할 수 없습니다."와 함께 노드·연결 목록으로 같은 내용을 본다. 움직임 줄이기 설정을
  켜면 자동 회전과 애니메이션이 꺼진다.
- 그래프의 배치·카메라 위치는 새로 고치면 초기화된다. 노트 본문과 위키링크만 서버에 저장된다.
  AI 유사도 관계는 재계산되는 cache이며 "모든 링크가 영구 저장"되는 것은 아니다.
- 관계 종류(위키링크, 수동 링크, AI 유사도, 소속)는 색과 범례로 구분된다. AI 유사도에는 점수·모델·
  분석 시각이 함께 표시된다.
- 노트마다 "Agent 사용"을 켜고 끌 수 있다. 켜진 노트만 내 Agent 답변의 근거로 쓰인다.
- **Vault는 나만 볼 수 있다.** 같은 조직의 관리자도 열람할 수 없다. 회사를 바꿔도 내 노트의 소유자는
  바뀌지 않는다.
- 개인 Vault에도 LLM Wiki가 있다(8절). 원본 등록·조사·게시 모두 소유자만 한다.

## 7. 회비·지출·영수증

### 회비
- `/finance/dues`에서 내 회비 청구·납부 상태를 본다(일반 구성원은 본인 내역만 보인다).

### 실지출 입력 (`/finance/transactions`)
- 지출은 금액·사용처 → 날짜·선택 시각 → 계정·예산 → 메모 → 영수증 → 명시 확인 순서로 입력한다.
  금액은 KRW 정확한 값이다. 저장에 성공하면 **바로 확정 장부에 기록**되며 금액 수정 버튼은 없다.
  잘못 넣었으면 관리자에게 정정 절차를 요청한다.
- 영수증은 JPEG/PNG/PDF만, 파일당 10MiB, 한 지출에 5개/25MiB까지다. 업로드 상태(대기/완료/실패/
  재시도/제거)는 글로 표시된다. 영수증이 없으면 "영수증 미첨부 사유"를 적어야 한다.
- 저장된 영수증은 이름·형식·크기만 보이고 **"원본 다운로드"**로만 받는다. 브라우저 안 미리보기는
  없다. 저장된 뒤에는 삭제·교체할 수 없고 "영수증 추가 저장"으로 감사 이력과 함께 덧붙일 수만 있다.
- 영수증 검사는 파일 형식과 손상 여부 확인이다. 바이러스 검사나 문자 인식(OCR)이 아니며, 금액·날짜를
  자동으로 읽어 주지 않는다.
- 전표 목록은 10건씩 보이고 수입·초안·과거 전표도 기본 필터에 포함된다. 옛 기록에 사용처가 없으면
  "기존 기록 · 사용처 정보 없음"으로 표시되며 값을 추측하지 않는다.

### CSV로 여러 지출 가져오기 ("CSV 지출 가져오기")
1. UTF-8 CSV 파일을 올린다(5MiB, 10,000행, 20열까지).
2. 헤더 매핑 추천을 확인하고 "추천을 포함한 헤더 매핑을 직접 확인했습니다."를 체크한다.
   CSV 계정 코드는 회사의 활성 지출 계정과 직접 짝지어야 한다.
3. 25행씩 검토한다. 오류 행이 있으면 적용할 수 없고, 제외할 행은 직접 "제외"를 체크한다. 이미
   가져온 것과 같은 행은 "중복 재사용 확인"을 체크해야 기존 기록을 재사용한다. 같은 값의 두 행은
   서로 다른 지출로 저장된다.
4. 영수증 없는 행이 있으면 가져오기 전체에 미첨부 사유를 한 번 적는다.
5. "검토한 선택 행 적용"을 누르면 전부 저장되거나 전부 취소된다. 일부만 저장되는 일은 없다.
- 미리보기를 고치면 새 미리보기가 만들어진다. 적용 중 연결이 끊기면 같은 화면에서 재시도하면
  이미 처리된 결과를 그대로 받는다. "복구 기록" job ID를 보관하면 나중에 상태를 확인할 수 있다.
- 올린 원본은 **24시간 뒤 만료**된다. 만료 뒤에는 "만료되었습니다. 원본과 민감한 값을
  폐기했습니다. 파일을 다시 선택해 새 검토를 시작하세요."가 나오고 파일을 새로 골라야 한다.
  이미 적용된 결과는 만료와 무관하게 장부에 남는다.
- 미리보기 합계는 "선택 미리보기 합계 … (아직 장부 지출 아님)"으로 표시되며 확정 금액이 아니다.
- CSV 원본은 외부 AI에 보내지 않으며 로그로 남지 않는다.

## 8. 결재 (`/approvals`)
- **내 요청**과 결정할 요청을 나눠 본다. 새 요청은 양식(일반 요청/지출 검토/구매 요청)을 고르고
  제목·목적을 쓴다. 금액형 양식은 KRW 금액이 필수다. "임시저장"은 draft, 제출 뒤 pending이다.
- 지출 검토에는 영수증을 첨부한다(7절과 같은 형식·크기 규칙). 제출 뒤에는 첨부를 추가·교체·삭제할
  수 없다.
- 결정자는 "승인 결정" / "반려 결정" / "보류 결정"을 한다. 반려는 사유를 비울 수 없다. 내 요청을 내가
  결정할 때는 확인 체크가 필요하고 기록에 남는다. 고액 결재와 legacy 조직의 결정은 비밀번호
  재인증을 요구할 수 있다.
- 결정할 수 있는 요청의 기준은 조직 저장소에 따라 다르다. legacy 조직은 **실제 배정된 결재 단계**에
  있어야 하고, PG 회사는 회사 결정자 pool에 속해야 한다. "배정된 단계가 아닙니다"는 오류가 아니라
  권한 안내다.
- 보류 중인 요청은 완료되지 않은 상태로 남고 보류한 사람이 다시 진행한다.
- 승인·반려된 요청은 바뀌지 않는다. 다시 올리려면 "재상신 초안 생성"으로 원본에 연결된 **새 초안**을
  만든다. 아직 결정 전인 내 요청은 "요청 철회"로 거둘 수 있다.
- 첨부 원본은 요청자와 실제 결정자만 "원본 다운로드"로 받는다.

## 9. 분석 (`/analytics`)
- 기간(`시작 ~ 종료`, 종료일 제외)과 시간대(기본 Asia/Seoul)를 정해 현재 활성 구성원, 기간 생성
  업무, 현재 열린·지연 업무, 기간 수입·비용·차액·전표 수, 활성 예산과 집행률, 기간 생성·결정 결재
  수를 본다. 기본 기간은 이번 달 첫날부터 다음 달 첫날이다.
- 각 카드는 서버가 준 상태를 라벨로 그대로 보인다. "조회 완료", 값이 0인 "데이터 없음",
  "원천 권한 없음", "기능 꺼짐", "사용 불가"는 서로 다르며 어느 것도 0으로 대체되지 않는다.
  "사용 불가"에는 이유 설명과 코드가 붙는다(예: PG 회사의 AI 사용량·감사 카드는 "이 저장소/범위에서
  지원하지 않는 원천" `SOURCE_UNSUPPORTED`, 여러 통화가 섞인 기간은 `MIXED_CURRENCY`).
- 금액은 장부 단위 그대로 표시된다. 예산이 없으면 집행률은 값 대신 해당 없음으로 표시된다.
- 기준이 "현재 상태 (과거 말일 상태 아님)"인 카드(구성원, 열린 업무, 활성 예산)는 조회 시점
  상태이고 과거 기간을 골라도 그때의 상태로 바뀌지 않는다. "선택 기간 흐름 [시작, 종료)" 카드만
  기간을 따른다. 추세 화살표나 이전 기간 비교는 서버가 제공한 경우에만 표시된다.
- 결재 지표는 요청자 권한만 있으면 내 요청만, 결정자 권한이 있으면 회사 범위로 집계된다.
- 보고서(구성원/업무/전표/예산/결재 생성/결재 결정)는 CSV로 내보낼 수 있다. 화면 안내대로
  **"다운로드할 때 저장된 필터와 현재 권한으로 원천 데이터를 다시 조회"**하므로 만들 때의 행 수와
  다를 수 있다. 100,000행을 넘으면 기간을 좁히라는
  안내가 나오며 일부만 잘려 나가지 않는다. 내보내기 요청은 일정 시간 뒤 만료된다.

## 10. 조직 지식 그래프와 LLM Wiki (`/documents/graph`, `/vault/graph`)
- 회사 문서 그래프와 개인 Vault 그래프는 같은 조작법(6절)을 쓴다. 회사 그래프는 문서·프로젝트
  공간·링크 관계를 보이고, 내가 볼 권한이 없는 문서는 숨김이 아니라 아예 포함되지 않는다.
- 문서를 선택하면 본문을 편집·저장할 수 있다. 다른 사람이 먼저 저장했으면 충돌 안내가 나오고 내
  편집은 유지된다.

### Wiki 흐름: 원본 → 검토 전 조사 → 초안 검토 → 명시적 게시
1. **원본 등록**: 선택한 노트/문서를 "선택 원본 등록"하거나 `.md/.txt` 파일(1,000,000바이트까지)을
   올린다. 원본은 등록 시점의 **불변 revision**으로 보관되며 내 원래 노트·문서는 바뀌지 않는다.
2. **조사**: 질문(4,000자까지)을 쓰고 "원본 검색"과 "게시 위키 검색" 중 하나 이상을 켠다. 게시된
   위키가 0개여도 원본만으로 조사할 수 있다. 결과는 **"검토 전 모델 생성 결과"**로 표시되고 인용은
   원본 revision의 정확한 구간으로 연결된다. "인용 위치 확인됨 · 사실 검증 아님"은 인용이 실제
   원문에 있다는 뜻일 뿐 내용이 맞다는 보증이 아니다. 근거가 없으면 "근거 없음 · 답변할 수 없습니다"가
   나오며 답변이 만들어지지 않는다.
3. **초안**: 쓰기 권한이 있으면 조사 결과를 "이 결과를 검토 초안으로 보관"하거나, 선택 원본으로
   "선택 원본 위키 초안 생성"(ingest), 게시 위키에 대해 "게시 위키 검토 초안 생성"(lint)을 만든다.
   초안은 일반 목록·그래프·검색에 나오지 않고 검토 화면에만 보인다.
4. **검토·게시**: 초안은 페이지별로 이전 내용과 게시할 내용을 나란히 보인다. "이 정확한 변경 묶음을
   검토했습니다"를 체크하고 "명시적으로 게시"를 누르면 그 digest에 대해서만 게시된다. 검토 중 초안이
   바뀌었거나 원본이 최신이 아니면(`stale`) 게시가 거절되고 다시 검토해야 한다. "이 묶음 거절"로
   버릴 수 있다.
5. **게시 위키**: 게시된 페이지·entity·concept는 목록과 3D 그래프, `index.md`/`log.md`/`schema.md`로
   본다. 페이지의 "게시 이력 보기"로 과거 버전을 보고, "위키 수동 편집"은 바로 반영되지 않고 새
   검토 초안이 된다.

### 작업 상태와 한계
- 작업 상태는 접수됨 / 조사 중 / 완료 · 검토 전 / 실패 / 사용 불가다. 작업 ID는 화면을 열어 둔 동안만
  보관되므로 "저장한 작업·초안 다시 열기"에 쓰려면 ID를 따로 적어 둔다.
- **사용 불가**는 로컬 모델이 꺼져 있거나 원본이 바뀌어 작업이 무효화된 상태(`SOURCE_REVOKED`)다.
  답변이나 게시물이 아니며, 그동안에도 원본 등록과 게시 위키 읽기는 계속 된다. 모델이 돌아오면
  "명시적 재시도"(최대 3회)를 누른다. 원본이 바뀐 경우에는 새 작업이 필요하다.
- 원본이 나중에 수정되면 그 원본을 쓴 페이지는 `stale`로 표시된다. 원본이 삭제되거나 내 권한이
  회수되면 그 원본에서 파생된 내용은 나에게 `unavailable`이 된다.
- 위키 모델은 회사 서버의 **로컬 모델만** 쓰며 원문을 외부 서비스로 보내지 않는다. 모델은 내 노트나
  ERP 데이터를 수정할 수 없다.

## 11. 인수인계
- `/handover`에서 인계 패키지를 만들고 "자료 수집"을 누르면 미완료 업무·반복 업무·핵심 문서·반복
  일정이 자동 수집된다.
- 비밀번호 등 민감 정보는 자동으로 제외된다.
- 필수 항목을 모두 체크하고 전임·후임·관리자 3인이 확인해야 완료된다.
