## 진행 순서 요약

1. HR-003 3~5단계(신청·승인·반영) — 기존 백엔드 API 위에 전용 화면(`LeaveScreen.tsx`) 신설, 업무대행 선택란 추가, `AttendanceScreen`에서 휴가 섹션 분리.
2. HR-003 1·2·6단계(정책·부여·통계) — `/hr/leave`에 권한 기반 "관리" 탭 추가, `leave_policy` 테이블 신규, 소진율에 산식+기준시각 함께 반환(SFR-028).
3. HR-004(모집·온보딩) — `/hr/recruitment`에 "채용 파이프라인"/"온보딩 체크리스트" 탭 신설, 백엔드 버그 2건 수정(전체 지원자 조회 깨짐, 감사로그 누락 2곳), 계정초대는 기존 `POST /members/invites` 재사용.

각 단위마다 백엔드 테스트, 프론트 `tsc -b`/route parity 테스트, 헤드리스 브라우저 실사용 흐름 검증을 거쳤다 (현재 백엔드 26/26, 프론트 59/59 통과).

## 남은 일

- **HR-001(구성원 프로필)**: 미착수. 백엔드에 단건 조회 API, 소속·직책 이력 테이블이 없어 세 화면 중 가장 큰 단위 — 새로 설계 필요.
- **크로스팀 논의 필요 항목**:
  - 결재함(`/approvals`)에서 승인해도 `leave_request` 상태·잔여일수가 갱신 안 되는 동기화 버그 — 전자결재(SFR-020) 담당자와 논의 필요. (`hr-leave-workflow.md` 참고)
  - 지원자 개인정보 자동 파기(6개월 보존기한 만료 시 삭제) — 스펙상 HR-004가 아니라 **ADM-004(데이터 보존·내보내기)** 담당 영역. 코드베이스에 스케줄러 인프라가 전무해 새로 만들어야 함. (`hr-recruitment-workflow.md` 참고)
