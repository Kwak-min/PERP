# 개인 그래프 / Wiki 클라우드 전송 동의

## 기본값과 자격 증명

- 개인 노트 저장·자동 분석과 기존 다시 분석 버튼은 로컬 전용이다. `vaultPref` 기본값이나 `agent_enabled`는 외부 전송 동의로 사용하지 않는다.
- 클라우드 전송은 실제 사용자가 전송 미리보기를 요청하고, 표시된 범위의 확인 체크박스를 선택한 뒤 실행 버튼을 눌러야 한다.
- 개인 소유 범위에는 **서버 공용 OpenRouter 키만** 적용한다. PG 개인 Wiki는 선택 회사와 독립적이므로 회사별 개인 키를 추측하거나 빌려 쓰지 않는다. 공용 키가 없으면 명시적 사용 불가다.
- 실제 `personal` 등급을 유지하여 전송한다. `public/internal/personal`만 허용하고 `sensitive/confidential/unknown`은 클라우드 전송하지 않는다. 기존 SQLite 노트 참고 제외도 원본과 후보 모두에 적용한다. PG의 참고 허용 capability placeholder를 저장된 동의로 해석하지 않는다.

## 정확한 동의 범위

- 미리보기에는 공급자, 공용 키 정책, 모델, 승인 사용자, 만료 시각, 범위 SHA-256 및 전체 입력이 표시된다.
- 그래프는 선택 노트와 최대 32개 인가된 후보를 고정한다. 제목, 원본 판, 등급, 전체 본문 해시, 실제 전송 문자열을 표시한다. 전송 문자열은 기존 임베딩 입력 규칙에 따라 제목과 본문 앞 6,000자다. 범위 확인 후 새로 만들어진 노트는 자동으로 추가하지 않는다.
- Wiki는 질문·스키마·컴파일러 지침·카탈로그와 원본/게시 페이지의 전체 입력 manifest를 표시한다. 동의는 요청, 모델 설정, 전체 manifest에 결합되며 원본의 전이 의존성도 검증한다.
- 미승인 token은 사용자/소유 범위에 결합된 5분짜리 일회성 서버 capability다. 승인하지 않은 미리보기는 공급자에 접속하지 않는다. 확인 취소 API는 token을 폐기한다. 위키 입력 선택 변경 시 UI 확인도 초기화한다.
- 승인 시 원본 판·내용·등급·참고 허용·현재 권한을 재검사한다. 그래프는 모델 목록 조회 후 본문 전송 직전과 결과 수락 직전에도 재검사한다. Wiki는 기존 fresh manifest/lease/fence 검사에 동의 및 참고 제외 검사를 추가한다. 수정·삭제·권한 회수된 범위는 그대로 전송/수락하지 않는다.
- token 재사용, 다른 사용자, 다른 원본/질문/모델, 만료 또는 취소된 확인은 거절한다. 이미 전송한 바이트를 사후에 취소할 수 있다고 표시하지 않는다.

## 결과와 재시도

- 그래프는 진짜 임베딩 응답의 인덱스·차원·유한수·영벡터를 검사한 후에만 cosine 관계를 저장한다. 실제 공급자와 동의 receipt 및 전체 후보 판을 결과 provenance에 기록한다.
- 캐시는 개인 소유자별이다. 승인한 후보의 판이 바뀌거나 삭제되면 해당 범위의 파생 관계도 무효화한다.
- Wiki 승인은 외부 전송에 대한 승인일 뿐 게시 승인이 아니다. 원본 불변성, 정확한 인용, 검토 전 결과/초안, 별도 명시적 게시 확인을 유지한다.
- 승인된 Wiki 작업에는 동의 receipt가 기존 durable job snapshot에 저장된다. 명시적 재시도는 원래 승인한 동일 범위에만 적용되고 기존 최대 3회 정책을 따른다. 변경된 범위는 새 미리보기/승인이 필요하다. 접수된 작업은 기존 작업 취소 기능으로 취소한다.
- 그래프 재시도는 새 미리보기/승인을 요구한다. 클라우드 장애를 로컬/echo 성공으로 바꾸지 않는다.

## 배포 설정과 수명

필요한 설정 이름:

- `OPENROUTER_API_KEY`
- `OPENROUTER_BASE_URL`
- `ORBITFLOW_EXTERNAL_MODEL`
- `ORBITFLOW_VAULT_OPENROUTER_EMBEDDING_MODEL`

로컬 옵션은 기존 `ORBITFLOW_VAULT_EMBEDDING_MODEL`, `OLLAMA_BASE_URL`, `WIKI_LOCAL_MODEL_CONFIG`를 사용한다.

미승인 token은 메모리에만 보관하며 최대 256개다. 현재 단일 API 인스턴스 배포를 대상으로 한다. 미리보기와 승인은 같은 인스턴스로 연결되어야 하며 재시작/인스턴스 변경 시 다시 확인한다. 이미 접수된 Wiki 작업과 receipt는 기존 DB에 남으므로 재시작 후에도 fresh 검사를 거쳐 처리한다. DB migration이나 새 비밀값은 추가하지 않았다.

검증은 격리 SQLite/네이티브 PostgreSQL, 실제 API/worker, 빌드된 SPA/Chrome 및 합성 OpenRouter fixture에서 수행한다. 이 문서는 실제 사용자 자료의 자동 외부 전송이나 운영 DB 변경을 허가하지 않는다.
