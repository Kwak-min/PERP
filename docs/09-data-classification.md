# 09. 데이터 분류 정책

## 등급 (DAR-004)
| 등급 | 정의 | 예시 | 마스킹 | 외부 LLM | 내보내기 | 보존 |
|---|---|---|---|---|---|---|
| 공개 | 조직 내 누구나 | 공지, 조직 프로필, 공개 일정 | - | 허용 | 허용 | 조직 정책 |
| 내부 | 구성원 대상 | 프로젝트, 업무, 문서, 자산 | - | 조직 정책 허용 시 | 권한 기반 | 조직 정책 |
| 개인 | 특정 개인 식별 | 연락처, 주소, 생년월일, 개인 회비 내역 | 기본 마스킹 | 기본 차단(익명화 후 허용) | 승인 필요 | 탈퇴 후 정책 기간 |
| 민감 | 노출 시 피해 큼 | 인사평가, 지원자 정보, 근태 사유, 회계 상세 | 강제 마스킹 | **차단** | 승인+감사 | 목적 달성 후 파기 |
| 고기밀 | 시스템 신뢰 근간 | 인증키, OAuth 토큰, 비밀번호 해시, 백업 키 | 노출 금지 | **차단** | 금지 | 키 순환 정책 |

## 통제 일관성 규칙
동일 필드는 **권한 / 내보내기 / 로그 / AI 요청** 네 경로에서 동일하게 통제된다. 한 경로만 막는 구현은 결함으로 본다.
- 로그·트레이스에 민감/고기밀 값 기록 금지 (구조화 로그 마스킹 필터).
- 자동화 실행 로그의 입력·결과값도 동일 마스킹 (AUT-002).
- 내보내기 파일은 암호화 + 만료 링크 + 권한 재검증(PER-006).

## 보존·삭제 (DAR-008)
| 데이터 | 기본 보존 | 삭제 방식 |
|---|---|---|
| 회계 거래·증빙 | 마감 후 5년(조직 설정) | legal hold 우선, 이후 hard delete |
| 감사로그 | 3년 이상 | 삭제 불가(append-only), 만료 후 아카이브 |
| 지원자 정보 | 채용 종료 후 6개월(기본) | 자동 파기 + 감사 기록 |
| 탈퇴 회원 개인정보 | 정책 기간 후 익명화 | 익명화(업무 이력은 보존) |
| AI 대화·기억 | 사용자 제어 | 즉시 삭제 + 인덱스 반영 |
| 파일 | 문서 정책 상속 | soft delete → 휴지통 → hard delete |

보존 정책 실행 결과와 예외 사유는 감사로그에 남는다. 영구삭제는 재인증 + 영향범위 확인 후 수행한다.

## 데이터 품질 (DAR-003)
저장·가져오기 시 필수/형식/중복후보/코드 유효성/참조 무결성 검사. 오류 행·사유·수정방법을 파일로 제공하고, **오류 데이터는 확정 저장하지 않는다**. 가져오기는 dry-run → 미리보기 → 확정 순서이며 부분 확정되지 않는다(DAR-009).

## 용어 사전 (DAR-002)
조직 유형별 표시 용어를 공통 개념 코드에 매핑한다. 예: `MEMBER_ATTENDANCE` → 기업 "근태", 동아리 "활동 참여", 연구실 "연구활동", 학생회 "행사활동". 버전·적용일·승인자를 관리하고, 용어 변경 후에도 과거 데이터 조회·보고가 가능해야 한다.
